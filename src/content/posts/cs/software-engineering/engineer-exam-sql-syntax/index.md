> **이번 글의 질문**
>
> - 정보처리기사 실기에서 조건문을 보고 **감점 없이 SQL 쿼리를 직접 작성**하려면 어떤 문법 구조를 암기해야 하나요?
> - 복잡한 쿼리의 실행 결과 표를 도출할 때 수험생이 가장 많이 틀리는 **NULL 연산, COUNT/AVG 분모, NOT IN, CASCADE 함정**은 어떤 기준으로 판별하나요?

> **핵심 요약**
>
> - SQL 문법은 **작성 순서**(SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY)와 **실제 실행 순서**(FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)를 구분하여 이해합니다.
> - 집계함수(SUM, AVG, COUNT(컬럼))는 NULL을 아예 없는 행처럼 제외하고 계산하며, 오직 `COUNT(*)`만 NULL을 포함합니다.
> - 모든 문법은 **실행 SQL 구문**(`SQL`)과 **실행 결과 표**(`OUTPUT`)를 짝지어 눈으로 데이터 변화를 확인하며 정리합니다.

## 1. SQL 명령어 분류와 내부 실행 순서 확인

정보처리기사 실기에서 SQL 파트는 크게 단답형 분류 문제, SQL 구문 직접 작성 문제, 그리고 쿼리 실행 결과 도출 문제로 나뉩니다. 먼저 SQL 명령어의 4대 분류 체계와 DBMS 내부 실행 순서를 비교합니다.

### 1.1 SQL 명령어 4대 분류 체계

| 분류 | 영문 원어 (한글명) | 핵심 역할 및 목적 | 소속 명령어 |
| --- | --- | --- | --- |
| DDL | **Data Definition Language**<br>(데이터 정의어) | 테이블, 스키마, 도메인, 뷰, 인덱스를 **생성·변경·삭제**하고 제약조건을 정의합니다. | CREATE, ALTER,<br>DROP, TRUNCATE |
| DML | **Data Manipulation Language**<br>(데이터 조작어) | 테이블에 저장된 실제 데이터(튜플)를 **조회·삽입·수정·삭제**하는 데 사용합니다. | SELECT, INSERT,<br>UPDATE, DELETE |
| DCL | **Data Control Language**<br>(데이터 제어어) | 데이터 보안, 무결성 유지, 사용자 **접근 권한 부여 및 회수**를 수행합니다. | GRANT (부여),<br>REVOKE (회수) |
| TCL | **Transaction Control Language**<br>(트랜잭션 제어어) | 트랜잭션의 작업 결과를 **영구 반영하거나 취소**합니다. (넓은 의미에서 DCL에 포함) | COMMIT, ROLLBACK,<br>SAVEPOINT |

### 1.2 SQL 문법 작성 순서와 내부 실행 순서 비교

코드를 작성하는 순서와 데이터베이스 옵티마이저가 실제로 절(Clause)을 처리하는 순서는 다릅니다. 이 실행 순서의 차이 때문에 별칭(Alias)과 집계함수의 사용 가능 위치가 결정됩니다.

| 구분 | 진행 단계 순서 | 실기 시험 판별 기준 |
| --- | --- | --- |
| 문법 작성 순서<br>(셀-프-웨-그-해-오) | **1) SELECT → 2) FROM → 3) WHERE → 4) GROUP BY → 5) HAVING → 6) ORDER BY** | 이 순서가 뒤바뀌면 구문 오류(Syntax Error)가 발생합니다. HAVING은 반드시 GROUP BY 뒤에 작성합니다. |
| 내부 실행 순서<br>(프-웨-그-해-셀-오) | **1) FROM → 2) WHERE → 3) GROUP BY → 4) HAVING → 5) SELECT → 6) ORDER BY** | • WHERE절(2단계)은 GROUP BY(3단계) 이전에 실행되므로 **WHERE절에는 집계함수를 사용할 수 없습니다.**<br>• SELECT절(5단계)에서 정의한 별칭은 WHERE절에서는 못 쓰지만 **ORDER BY절(6단계)에서는 사용할 수 있습니다.** |

### 1.3 실기 답안 작성 시 감점 방지 4대 기준

| 구분 | 작성 기준 | 올바른 표기 | 감점 표기 |
| --- | --- | --- | --- |
| 대소문자 구분 | SQL 예약어(SELECT, FROM 등)와 테이블·컬럼명은 대소문자를 구분하지 않습니다. 단, **작은따옴표(' ') 안의 문자열 리터럴은 대소문자를 엄격히 구분**하므로 문제 지문과 동일하게 적습니다. | `등급 = 'VIP'` | `등급 = 'vip'` |
| 따옴표 구분 | 문자열과 날짜 데이터에는 반드시 작은따옴표를 붙이고, 숫자 데이터에는 따옴표를 붙이지 않습니다. | `이름 = '홍길동'`<br>`점수 >= 90` | `이름 = 홍길동` |
| 세미콜론(;) 표기 | 별도의 생략 지시가 없다면 SQL 문장 끝에 세미콜론(;)을 붙여 문장 종료를 명확히 표시합니다. | `... FROM 사원;` | `... FROM 사원` |
| 전치사 키워드 세트 | 짝을 이루는 전치사 키워드를 빠뜨리지 않도록 세트로 암기합니다.<br>• `INSERT INTO` 테이블명<br>• `DELETE FROM` 테이블명<br>• `UPDATE` 테이블명 `SET`<br>• `GRANT` 권한 `ON` 테이블 `TO` 사용자<br>• `REVOKE` 권한 `ON` 테이블 `FROM` 사용자 | `INSERT INTO`<br>`DELETE FROM` | `INSERT` (INTO 누락)<br>`DELETE` (FROM 누락) |

## 2. 데이터 정의어(DDL)와 참조 무결성 제약조건 정리

데이터 정의어(DDL)는 테이블과 뷰, 인덱스의 구조를 정의하거나 변경합니다. 특히 CREATE TABLE의 제약조건과 ON DELETE CASCADE 연쇄 삭제 옵션은 실기 시험에서 가장 자주 출제되는 항목입니다.

### 2.1 테이블 생성(CREATE TABLE)과 6대 제약조건 비교

*SQL — CREATE TABLE 표준 구문 예시 (DDL)*

```sql
CREATE TABLE 학생 (
    학번 CHAR(8) NOT NULL,
    이름 VARCHAR(20) NOT NULL,
    학과 VARCHAR(30) DEFAULT '컴퓨터공학과',
    학년 INT CHECK (학년 >= 1 AND 학년 <= 4),
    주민번호 CHAR(14) UNIQUE,
    지도교수번호 CHAR(5),
    PRIMARY KEY (학번),
    FOREIGN KEY (지도교수번호) REFERENCES 교수(교수번호)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);
```

| 제약조건 키워드 | 의미 및 무결성 분류 | NULL 허용 | 중복 허용 | 실기 판별 포인트 |
| --- | --- | --- | --- | --- |
| PRIMARY KEY<br>(기본키) | 튜플을 유일하게 식별하는 주키<br>(**개체 무결성** 보장) | 불가 (X) | 불가 (X) | 테이블당 1개만 지정 가능 (복합키 묶기 가능). NOT NULL + UNIQUE와 동일합니다. |
| FOREIGN KEY<br>(외래키) | 다른 테이블의 기본키(PK)를 참조<br>(**참조 무결성** 보장) | 허용 (O) | 허용 (O) | 반드시 REFERENCES 부모테이블(부모PK) 구문과 함께 작성합니다. |
| UNIQUE<br>(고유키/대체키) | 컬럼 내 중복된 값 저장을 방지 | 허용 (O)<br>(주의) | 불가 (X) | **기본키와 달리 NULL을 허용**하며, 여러 행에 NULL이 들어갈 수 있습니다. |
| NOT NULL | 빈 값(NULL) 입력을 금지 | 불가 (X) | 허용 (O) | 컬럼 정의 옆(컬럼 레벨)에만 직접 명시합니다. |
| CHECK (조건) | 허용 가능한 도메인 범위 제한<br>(**도메인 무결성** 보장) | 허용 (O) | 허용 (O) | 예: `CHECK (점수 >= 0 AND 점수 <= 100)` |
| DEFAULT 값 | 값 생략 시 자동 입력될 기본값 | \- | \- | 등호(=) 없이 `DEFAULT '일반'` 형태로 바로 값을 적습니다. |

### 2.2 외래키 참조 무결성 옵션 (ON DELETE / ON UPDATE)

부모 테이블의 행이 삭제되거나 기본키가 변경될 때, 이를 참조하는 자식 테이블의 튜플이 어떻게 처리되는지 결정하는 기준입니다.

| 옵션 | 명칭 | 부모 행 삭제 시 자식 테이블 동작 |
| --- | --- | --- |
| `ON DELETE CASCADE` | 연쇄 삭제 | 부모 테이블의 행이 삭제되면, 그 행을 참조하던 **자식 테이블의 관련 행들도 모두 자동으로 함께 삭제**됩니다. |
| `ON DELETE SET NULL` | NULL 치환 | 부모 테이블의 행이 삭제되면, 자식 테이블의 외래키 컬럼 값을 **NULL로 변경**합니다. |
| `ON DELETE RESTRICT`<br>`NO ACTION` | 삭제 거부<br>(생략 시 기본값) | 자식 테이블에서 참조 중인 행이 하나라도 있으면 부모 테이블의 **삭제 작업을 거부**합니다. |

> **[주의] 실기 빈출 함정 — 3단계 연쇄 삭제(ON DELETE CASCADE) 후 남은 행 수 계산**
>
> 부서 ← 사원 ← 가족이 모두 ON DELETE CASCADE로 연결되어 있을 때, `DELETE FROM 부서 WHERE 부서코드 = 'D1';`을 실행하면 사원에서 E1·E2가 삭제되고, 연쇄적으로 가족에서도 E1·E2의 가족 3명이 함께 삭제됩니다. 최종적으로 **사원 1건**(E3), **가족 1건**(E3 가족)만 남습니다.

*연쇄 삭제 전후 행 수 비교*

| 테이블 | 삭제 전 데이터 | 삭제 전 | 함께 삭제되는 행 | 삭제 후 |
| --- | --- | --- | --- | --- |
| 부서 | D1, D2 | 2건 | D1 (직접 삭제) | 1건 |
| 사원 | E1\[D1\], E2\[D1\], E3\[D2\] | 3건 | E1, E2 (D1 소속) | 1건 |
| 가족 | E1 가족 2명, E2 가족 1명, E3 가족 1명 | 4건 | E1 가족 2명 + E2 가족 1명 (3명) | 1건 |

### 2.3 테이블 변경(ALTER TABLE) 및 삭제(DROP / TRUNCATE)

*SQL — ALTER / DROP / CREATE VIEW / CREATE INDEX 핵심 구문 (DDL)*

```sql
-- 1. ALTER TABLE (컬럼 추가 / 수정 / 삭제 / 제약조건 추가)
ALTER TABLE 사원 ADD 이메일 VARCHAR(30);
ALTER TABLE 사원 MODIFY 이메일 VARCHAR(50) NOT NULL;   -- SQL Server는 ALTER COLUMN 사용
ALTER TABLE 사원 DROP COLUMN 이메일;                   -- 삭제 시에는 COLUMN 키워드 필수!
ALTER TABLE 사원 ADD CONSTRAINT PK_사원 PRIMARY KEY (사번);

-- 2. DROP TABLE (CASCADE: 참조하는 뷰/외래키까지 모두 삭제 | RESTRICT: 참조 중이면 삭제 거부)
DROP TABLE 사원 CASCADE;

-- 3. CREATE VIEW (AS 키워드 필수! 뷰 정의 변경 시 ALTER VIEW는 사용 불가!)
CREATE VIEW 개발부뷰 AS
SELECT 사번, 이름, 급여 FROM 사원 WHERE 부서 = '개발';

-- 4. CREATE INDEX (중복 불허 고유 인덱스를 사번 오름차순으로 생성)
CREATE UNIQUE INDEX IDX_사원번호 ON 사원(사번 ASC);
```

## 3. 데이터 조작어 I — INSERT · UPDATE · DELETE 기준

데이터 조작어(DML) 중 테이블의 내용을 변경하는 세 가지 명령어입니다. 다른 테이블의 데이터를 서브쿼리로 조회해 한꺼번에 삽입하거나 수정하는 패턴을 함께 확인합니다.

*SQL — INSERT / UPDATE / DELETE 문법 패턴 (DML)*

```sql
-- 1. INSERT INTO: 단일 행 삽입 (컬럼 지정 생략 시 전체 컬럼 순서대로 값 입력)
INSERT INTO 학생(학번, 이름, 학년) VALUES ('202601', '김철수', 3);

-- 2. INSERT INTO ... SELECT: 서브쿼리 결과를 다중 행으로 일괄 삽입 (VALUES 키워드를 쓰지 않습니다!)
INSERT INTO 우수학생(학번, 이름)
SELECT 학번, 이름 FROM 학생 WHERE 학점 >= 4.0;

-- 3. UPDATE ... SET: 조건에 맞는 행의 속성 값 변경 (WHERE 절 생략 시 테이블 전체 행이 변경됩니다!)
UPDATE 사원
SET 급여 = 급여 * 1.1, 직급 = '과장'
WHERE 부서 = '개발팀' AND 근속연수 >= 5;

-- 4. DELETE FROM: 조건에 맞는 행 삭제 (WHERE 절 생략 시 모든 튜플이 삭제되나 테이블 구조는 남습니다!)
DELETE FROM 사원
WHERE 퇴사여부 = 'Y';
```

## 4. 데이터 조작어 II — SELECT 조회, LIKE 패턴, NULL 4대 법칙

조회문(SELECT)에서는 중복을 제거하는 DISTINCT의 동작 방식, 문자열 와일드카드(%, \_), 그리고 실기 시험 오답률 1위인 NULL 처리 규칙에 시간을 더 씁니다.

### 4.1 SELECT DISTINCT와 LIKE 와일드카드(% vs \_) 비교

| 항목 | 동작 기준 | 예시 |
| --- | --- | --- |
| 다중 컬럼 DISTINCT | 첫 번째 컬럼만 보는 것이 아니라, **(부서, 직급) 두 값의 조합 전체가 완전히 똑같은 행만 하나로 합쳐서 제거**합니다. | `SELECT DISTINCT 부서, 직급 FROM 사원;` |
| 논리 연산자 우선순위 | 괄호가 없을 때 **NOT > AND > OR** 순서로 실행됩니다. | `A OR B AND C`<br>→ B AND C가 먼저 묶임 |
| LIKE 와일드카드 | **%는 0글자 이상의 모든 문자**, **\_(언더바)는 정확히 1글자**를 의미합니다. | `'김%'`, `'김_'` |

| LIKE 조건식 | 정확한 매칭 기준 | 매칭 성공 (O) | 매칭 실패 (X) |
| --- | --- | --- | --- |
| `이름 LIKE '김%'` | '김'으로 시작하는 모든 문자열 (1글자 포함) | '김', '김철', '김철수' | '이김', '박김철' |
| `이름 LIKE '김_'` | '김'으로 시작하고 **전체 길이가 정확히 2글자** | '김철', '김산' | '김' (1글자), '김철수' (3글자) |
| `이름 LIKE '_길%'` | **두 번째 글자가 '길'인** 2글자 이상 문자열 | '홍길', '홍길동', '김길수' | '길동' (첫 글자가 '길') |
| `이름 LIKE '%동_'` | **끝에서 두 번째 글자가 '동'인** 문자열 | '길동이', '홍동수' | '홍길동' (마지막이 '동') |

### 4.2 실기 오답률 1위 — NULL의 4대 법칙 정리

NULL은 숫자 0이나 공백('')이 아니라 **아직 정의되지 않은 미지의 값**(Unknown)입니다. 다음 네 가지 법칙을 기준으로 결과를 도출합니다.

| NULL 법칙 구분 | 핵심 동작 규칙 | 실기 함정 사례 및 해결 문법 |
| --- | --- | --- |
| 법칙 1. 산술 연산 | **NULL이 포함된 사칙연산 결과는 무조건 NULL**입니다. | `NULL + 100 = NULL`, `NULL * 0 = NULL`<br>(0을 곱해도 0이 아니라 NULL이 됩니다!) |
| 법칙 2. 비교 연산 | `=`, `<>`, `!=`, `>`, `<`로 NULL을 비교하면 결과는 **항상 UNKNOWN**(거짓)이 됩니다. | • `WHERE 보너스 = NULL` → **결과 0건!**<br>• 반드시 **IS NULL / IS NOT NULL** 사용!<br>• `WHERE 보너스 <> 500` 실행 시 NULL인 행도 함께 제외됩니다. |
| 법칙 3. 집계 함수 | SUM, AVG, MAX, MIN, COUNT(컬럼)은 **NULL 행을 아예 제외**하고 계산합니다. | • 오직 **`COUNT(*)`만 NULL 행을 포함**합니다.<br>• AVG(컬럼)은 전체 행 수가 아니라 **NULL이 아닌 행 수**로 나눕니다. |
| 법칙 4. 치환 함수 | 계산 전 NULL을 특정 값으로 바꿀 때 사용합니다. | • `NVL(컬럼, 0)` / `IFNULL(컬럼, 0)`<br>• `COALESCE(A, B, 0)`: 첫 비-NULL 값 반환<br>• `NULLIF(A, B)`: A=B이면 NULL, 다르면 A 반환 |

## 5. GROUP BY · HAVING 집계와 ORDER BY 정렬 기준

집계함수에서 NULL이 섞여 있을 때 COUNT와 AVG의 결과값이 어떻게 달라지는지 실제 코드와 출력 블록으로 비교합니다.

### 5.1 COUNT와 AVG의 NULL 처리 실습 비교

*기준 데이터: 성적 테이블 (4행)*

| 행 번호 | 점수 |
| --- | --- |
| 1 | 80 |
| 2 | 80 |
| 3 | 20 |
| 4 | NULL |

*SQL — 성적 테이블(점수: 80, 80, 20, NULL) 집계 쿼리 (DML)*

```sql
-- 성적 테이블에 4명의 점수 (80, 80, 20, NULL)가 저장되어 있을 때:
SELECT COUNT(*) AS C1,
       COUNT(점수) AS C2,
       COUNT(DISTINCT 점수) AS C3,
       SUM(점수) AS S1,
       AVG(점수) AS A1,
       AVG(COALESCE(점수, 0)) AS A2
FROM 성적;
```

*OUTPUT — 실행 결과 테이블*

| C1<br>(전체 행) | C2<br>(NULL 제외) | C3<br>(중복·NULL 제외) | S1<br>(합계) | A1<br>(NULL 제외 평균) | A2<br>(0 치환 후 평균) |
| --- | --- | --- | --- | --- | --- |
| 4 | 3 | 2 ({80, 20}) | 180 | 60 (180 ÷ 3) | 45 (180 ÷ 4) |

위 결과에서 AVG(점수)는 전체 4명이 아니라 NULL을 제외한 3명을 분모로 삼아 180 ÷ 3 = 60이 도출됩니다. 만약 COALESCE(점수, 0)이나 NVL(점수, 0)으로 NULL을 0점으로 바꾼 뒤 평균을 구하면 분모가 4명이 되어 45가 출력됩니다.

### 5.2 WHERE 절과 HAVING 절의 역할 구분 및 다중 정렬

*SQL — WHERE + GROUP BY + HAVING + ORDER BY 복합 쿼리 (DML)*

```sql
SELECT 부서, COUNT(*) AS 인원수, AVG(급여) AS 평균급여
FROM 사원
WHERE 직급 <> '인턴'          -- 1단계: 그룹화 전에 개별 사원 중 '인턴'을 먼저 제외합니다.
GROUP BY 부서                 -- 2단계: 남은 사원들을 '부서' 단위로 그룹핑합니다.
HAVING AVG(급여) >= 3000      -- 3단계: 그룹별 평균급여가 3000 이상인 부서 그룹만 남깁니다.
ORDER BY 인원수 ASC, 평균급여 DESC; -- 4단계: 인원수 오름차순 정렬 후, 동률일 때만 평균급여 내림차순 정렬합니다.
```

## 6. 조인(JOIN) 4종과 집합 연산자 결과 비교

조인(JOIN)은 두 테이블을 **수평(열 방향)으로 결합**하고, 집합 연산자(UNION 등)는 두 쿼리 결과를 **수직(행 방향)으로 결합**합니다. 기준 테이블 두 개를 두고 조인 방식에 따라 결과 행 수가 어떻게 달라지는지 비교합니다.

### 6.1 INNER JOIN vs OUTER JOIN 실행 결과 비교

*기준 데이터 ① 사원 테이블 (4건)*

| 사번 | 이름 | 부서 |
| --- | --- | --- |
| 101 | 김철수 | D1 |
| 102 | 이영희 | D2 |
| 103 | 박민수 | D2 |
| 104 | 최지훈 | NULL |

*기준 데이터 ② 부서 테이블 (3건)*

| 부서 | 부서명 |
| --- | --- |
| D1 | 인사팀 |
| D2 | 개발팀 |
| D3 | 영업팀 |

| 조인 종류 | 핵심 결합 규칙 및 구문 | 결과 행 수 | 포함/제외되는 튜플 |
| --- | --- | --- | --- |
| INNER JOIN<br>(내부 조인) | 양쪽 테이블에 조인 키가 **모두 존재하는 행만** 추출합니다.<br>(NATURAL JOIN은 공통 컬럼 중복까지 제거) | 3행 | 매칭된 101, 102, 103만 출력 (최지훈·영업팀 제외) |
| LEFT OUTER JOIN<br>(왼쪽 외부 조인) | 왼쪽(사원) 테이블의 모든 행을 유지하고, 오른쪽 미매칭 속성은 NULL로 채웁니다. (Oracle: `E.부서 = D.부서(+)`) | 4행 | 매칭 3행 + **(최지훈, NULL)** 추가 |
| RIGHT OUTER JOIN<br>(오른쪽 외부 조인) | 오른쪽(부서) 테이블의 모든 행을 유지하고, 왼쪽 미매칭 속성은 NULL로 채웁니다. (Oracle: `E.부서(+) = D.부서`) | 4행 | 매칭 3행 + **(NULL, 영업팀)** 추가 |
| FULL OUTER JOIN<br>(완전 외부 조인) | 양쪽 테이블의 미매칭 행을 모두 유지하고 빈자리를 NULL로 채웁니다. | 5행 | 매칭 3행 + (최지훈, NULL) + (NULL, 영업팀) |
| CROSS JOIN<br>(교차 곱) | 조인 조건 없이 가능한 모든 행을 곱합니다.<br>(**열 수 = 더하기, 행 수 = 곱하기**) | 12행<br>(4 × 3) | 차수(열) = 3 + 2 = 5열<br>기수(행) = 4 × 3 = 12행 |

### 6.2 집합 연산자 4종 (UNION vs UNION ALL · INTERSECT · EXCEPT)

| 연산자 | 집합 의미 | 결과 규칙 | 비고 |
| --- | --- | --- | --- |
| `UNION` | 합집합<br>(중복 제거) | 두 쿼리의 결과를 합치면서 **중복된 튜플을 1개로 제거**하고 자동 정렬합니다. | \- |
| `UNION ALL` | 합집합<br>(중복 포함) | 중복 제거와 정렬 없이 두 쿼리의 결과를 **단순히 위아래로 이어 붙입니다.** | 행 수 = 첫 쿼리 행 수 + 두 번째 쿼리 행 수 |
| `INTERSECT` | 교집합 | 두 쿼리 결과에 **공통으로 존재하는 행만** 추출합니다. | \- |
| `EXCEPT` / `MINUS` | 차집합 | 첫 번째 쿼리 결과에서 두 번째 쿼리 결과에 포함된 행을 뺀 나머지를 추출합니다. | 표준/MSSQL은 EXCEPT,<br>Oracle은 MINUS |

## 7. 서브쿼리 · 윈도우 순위 함수 · 그룹 확장 함수 정리

최근 실기 시험에서 변별력을 가르는 다중 행 서브쿼리 연산자(IN, ANY, ALL)와 윈도우 순위 함수(RANK, DENSE\_RANK, ROW\_NUMBER)를 비교합니다.

### 7.1 서브쿼리 위치별 명칭 및 다중 행 연산자

*위치별 서브쿼리 3분류 (단답형 필수 용어)*

| 번호 | 명칭 | 위치 | 특징 |
| --- | --- | --- | --- |
| 1 | 스칼라 서브쿼리<br>(Scalar Subquery) | SELECT 절 | 단일 값 반환 |
| 2 | 인라인 뷰<br>(Inline View) | FROM 절 | 임시 가상 테이블 역할 |
| 3 | 중첩 서브쿼리<br>(Nested Subquery) | WHERE 또는 HAVING 절 | 조건 비교에 사용 |

*ANY(하나라도 만족) vs ALL(모두 만족) — 서브쿼리 결과가 (10, 20, 30)일 때*

| 조건식 | 판단 기준 | 참이 되는 조건 |
| --- | --- | --- |
| `> ANY (10, 20, 30)` | 하나라도 크면 참 | **최솟값(10)보다 크면 참** |
| `< ANY (10, 20, 30)` | 하나라도 작으면 참 | **최댓값(30)보다 작으면 참** |
| `> ALL (10, 20, 30)` | 모든 값보다 커야 참 | **최댓값(30)보다 커야 참** |
| `< ALL (10, 20, 30)` | 모든 값보다 작아야 참 | **최솟값(10)보다 작아야 참** |

> **[주의] 빈출 함정 — NOT IN 서브쿼리 결과에 NULL이 포함된 경우**
>
> 서브쿼리 실행 결과에 NULL이 단 하나라도 포함되어 있다면(예: `WHERE 부서번호 NOT IN (10, 20, NULL)`), 이는 내부적으로 `부서번호 <> 10 AND 부서번호 <> 20 AND 부서번호 <> NULL`로 변환됩니다. 이때 `부서번호 <> NULL`이 항상 UNKNOWN이므로 AND 결합 전체가 거짓이 되어 **조회 결과는 무조건 0건**(공집합)이 됩니다!

### 7.2 윈도우 순위 함수 3대장 (RANK · DENSE\_RANK · ROW\_NUMBER)

*SQL — 동점자(급여 4000이 2명)가 있을 때 순위 함수 비교 (WINDOW FUNCTION)*

```sql
SELECT 이름, 급여,
       RANK() OVER (ORDER BY 급여 DESC) AS R1,
       DENSE_RANK() OVER (ORDER BY 급여 DESC) AS R2,
       ROW_NUMBER() OVER (ORDER BY 급여 DESC) AS R3
FROM 사원;
```

*OUTPUT — 순위 함수별 출력 결과 비교*

| 이름 | 급여 | R1: RANK()<br>(동점 허용 + 다음 순위 건너뜀) | R2: DENSE\_RANK()<br>(동점 허용 + 건너뛰지 않음) | R3: ROW\_NUMBER()<br>(동점 불허 + 고유 순번) |
| --- | --- | --- | --- | --- |
| 김부장 | 5000 | 1 | 1 | 1 |
| 이차장 | 4000 | 2 | 2 | 2 |
| 박차장 | 4000 | 2 | 2 | 3 |
| 최과장 | 3000 | 4 (3위 건너뜀!) | 3 (안 건너뜀!) | 4 |

### 7.3 그룹 확장 함수 (ROLLUP · CUBE · GROUPING SETS) 및 절차형 SQL

*그룹 확장 함수 3종 비교 (인자가 A, B 두 개일 때)*

| 함수 | 소계 조합 수 | 출력되는 집계 조합 | 핵심 특징 |
| --- | --- | --- | --- |
| `ROLLUP(A, B)` | n + 1개<br>(3개) | (A, B) 소계<br>(A) 소계<br>() 전체 총계 | 계층적 소계를 생성하며, **인자 순서가 바뀌면 결과도 달라집니다.** |
| `CUBE(A, B)` | 2ⁿ개<br>(4개) | (A, B) 소계<br>(A) 소계<br>(B) 소계<br>() 전체 총계 | 가능한 **모든 다차원 조합**의 소계를 생성합니다. |
| `GROUPING SETS(A, B)` | 지정한 개수<br>(2개) | (A) 소계<br>(B) 소계 | 괄호 안에 지정한 개별 속성별 소계만 구하며, **전체 총계는 나오지 않습니다.** |

*절차형 SQL 3종 구분*

| 종류 | 실행 방식 | 핵심 특징 |
| --- | --- | --- |
| 프로시저<br>(PROCEDURE) | 단독 호출 (`EXECUTE`) | 트랜잭션 일괄 작업을 처리합니다. |
| 사용자 정의 함수<br>(FUNCTION) | 쿼리 안에서 호출 | 반드시 `RETURN`으로 **단일 값을 반환**합니다. |
| 트리거<br>(TRIGGER) | DML 이벤트 발생 시 자동 실행 | 내부에 **COMMIT / ROLLBACK(TCL)을 사용할 수 없습니다.** |

## 8. 데이터 제어어(DCL) · 트랜잭션(TCL) · 관계대수 변환

권한을 부여·회수하는 DCL 구문 어순과 SAVEPOINT 롤백 추적, 그리고 관계대수 기호를 SQL로 바꾸는 공식입니다.

### 8.1 GRANT와 REVOKE 문법 어순 비교

*SQL — 권한 부여(GRANT ... ON ... TO) 및 권한 회수(REVOKE ... ON ... FROM) (DCL)*

```sql
-- 1. 권한 부여: GRANT 권한 ON 테이블 TO 사용자 [WITH GRANT OPTION];
GRANT SELECT, INSERT ON 학생 TO KIM WITH GRANT OPTION;

-- 2. 권한 회수: REVOKE 권한 ON 테이블 FROM 사용자 [CASCADE];
REVOKE SELECT, INSERT ON 학생 FROM KIM CASCADE;
```

| 구분 | 짝 키워드 | 선택 옵션 | 옵션 의미 |
| --- | --- | --- | --- |
| GRANT<br>(권한 부여) | `ON ~ TO` | `WITH GRANT OPTION` | 부여받은 권한을 다른 제3자 사용자에게도 다시 부여할 수 있는 위임 권한을 함께 줍니다. |
| REVOKE<br>(권한 회수) | `ON ~ FROM` | `CASCADE` | 해당 사용자의 권한뿐만 아니라, 그 사용자가 제3자에게 부여했던 권한까지 연쇄적으로 모두 회수합니다. |

### 8.2 관계대수(Relational Algebra) ↔ SQL 1:1 변환 기준

| 관계대수 연산자 | 기호 표기 예시 | 핵심 연산 의미 | 대응하는 SQL 구문 |
| --- | --- | --- | --- |
| Select (선택 연산) | σ 학과='컴퓨터' (학생) | 조건을 만족하는 **행(튜플)** 부분집합 추출 (수평 연산) | `SELECT * FROM 학생`<br>`WHERE 학과 = '컴퓨터';` |
| Project (추출 연산) | π 이름, 학과 (학생) | 지정된 **열(속성)** 부분집합 추출 및 **중복 자동 제거** (수직 연산) | `SELECT DISTINCT 이름, 학과`<br>`FROM 학생;` |
| Join (조인 연산) | 학생 ⋈ 학번=학번 성적 | 공통 속성을 기준으로 두 릴레이션을 결합 | `SELECT * FROM 학생`<br>`JOIN 성적 ON ...;` |
| Division (나누기) | 수강 ÷ 필수과목 | 오른쪽 릴레이션의 **모든 값을 빠짐없이 가진** 튜플만 추출 | 이중 NOT EXISTS 서브쿼리로 구현 |

| --- | --- | --- |
| 1번 | `ALTER TABLE 사원 ADD 이메일 VARCHAR(20);` | 컬럼 추가는 ADD 컬럼명 자료형 구문을 사용합니다. |

## 10. 다시 볼 때 기억할 핵심 문법 및 복습 체크리스트

시험 직전 빠르게 훑어볼 수 있도록 상황별 SQL 문법 공식과 주의점을 한눈에 정리합니다.

| 상황 및 조건 | 사용 문법 및 핵심 구문 | 주의점 및 판별 기준 |
| --- | --- | --- |
| 테이블에 새 컬럼을 추가하거나 삭제할 때 | • 추가: `ALTER TABLE T ADD 컬럼 타입;`<br>• 삭제: `ALTER TABLE T DROP COLUMN 컬럼;` | 삭제할 때는 반드시 COLUMN 예약어를 함께 적고, 수정할 때는 MODIFY(또는 ALTER COLUMN)를 씁니다. |
| 부모 키 삭제 시 자식 행도 자동 삭제할 때 | `FOREIGN KEY(FK) REFERENCES 부모(PK) ON DELETE CASCADE` | DELETE 문제에서 테이블 정의에 CASCADE가 있는지 반드시 먼저 확인합니다. |
| 그룹별 집계 결과에 조건을 걸어 필터링할 때 | `GROUP BY 기준컬럼 HAVING 집계함수(컬럼) >= 값` | WHERE 절에는 SUM, AVG, COUNT 등 집계함수를 절대 쓸 수 없습니다. |
| 매칭되지 않는 행까지 버리지 않고 조인할 때 | `LEFT / RIGHT / FULL OUTER JOIN ON 조건` | 매칭 실패 쪽 컬럼에는 NULL이 채워지며, Oracle (+) 기호는 부족한 쪽에 붙입니다. |
| 사용자에게 권한을 위임 부여하거나 연쇄 회수할 때 | • `GRANT 권한 ON T TO 유저 WITH GRANT OPTION;`<br>• `REVOKE 권한 ON T FROM 유저 CASCADE;` | GRANT는 TO, REVOKE는 FROM과 짝을 이룹니다. |
